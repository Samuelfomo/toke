Executive Summary

Le problème

Les entreprises camerounaises qui gèrent des équipes à horaires variables — centres d’appels, usines, hôtels, sociétés de sécurité, hôpitaux, retail — produisent encore leurs plannings hebdomadaires manuellement dans Excel. Ce processus mobilise plusieurs personnes 10 à 20 heures par semaine, génère des erreurs récurrentes, ne se boucle pas avec la présence réelle des employés, et empêche toute mesure d’efficacité.

Le cas pilote LMT (Light Management Technology) en est un exemple emblématique. LMT gère environ 250 agents répartis sur 15+ files d’attente clients (ENEO, BUCREP, UPOWA, PAM, VERICAM, et plusieurs autres). Leur planification s’appuie sur deux fichiers Excel : un calculateur Erlang C importé de Call Centre Helper, et un planning nominatif construit à la main. Les deux fichiers ne sont jamais synchronisés automatiquement et le shrinkage (taux d’absence/inactivité) est estimé “au doigt mouillé” parce qu’aucune donnée de présence réelle ne remonte vers le planning.

La solution

Toké, dans son état actuel, est une plateforme robuste de pointage géofencé, mémos validés et hiérarchie organisationnelle. Elle est commercialisable telle quelle pour des entreprises classiques. Pour adresser les besoins des entreprises à horaires variables, nous proposons d’ajouter deux nouveaux modules empilables :

  1. Module Planning (horizontal, vendable indépendamment) : gestion des shifts prévisionnels, calendrier mobile employé, contraintes RH, boucle pointage vs prévu. Adresse usines, hôtels, hôpitaux, retail, sécurité.
  2. Module Centre d’Appels (vertical, dépend du Module Planning) : forecasting via CSV standardisé, dimensionnement Erlang C, scheduling semi-automatique, dashboard temps réel d’adhérence, prédiction du niveau de service. Adresse les centres d’appels et services de relation client.

Le Module Planning est conçu comme une brique générique qui transforme Toké d’une plateforme de pointage en plateforme WFM (Workforce Management) complète. Le Module CC est l’instance verticale qui sert LMT comme client pilote.

Toké est commercialisé en licences modulaires :

1. Vision produit

1.1 De Toké Core à Toké Platform

Toké a été initialement conçu comme une solution de pointage géofencé pour les entreprises camerounaises et africaines. Le produit existant adresse parfaitement les entreprises où chaque employé pointe son heure d’arrivée et de départ, où les mémos justifient les écarts, et où la hiérarchie supervise par périmètre.

Le constat fait sur LMT — et qui s’applique à des dizaines de milliers d’autres entreprises sur le continent — est que dès qu’on sort du modèle “horaires fixes 8h-17h”, le besoin change radicalement. Les équipes tournent, les shifts varient, les compétences se croisent, et il faut planifier à l’avance ce que chaque employé doit faire à chaque heure de la semaine.

Ce besoin n’est pas un cas particulier. Il est partagé par :

  • Les centres d’appels (LMT, et tous les BPO)
  • Les usines avec rotations 3×8 ou 2×12
  • Les hôtels et restaurants (front desk, salle, cuisine, sécurité, étages)
  • Les hôpitaux et cliniques (gardes médicales et paramédicales, astreintes)
  • Les sociétés de sécurité privée (vacations sur sites multiples)
  • Les chaînes de magasins (rotations vendeurs, ouvertures/fermetures)
  • Les sociétés de nettoyage (équipes tournantes sur sites clients)
  • Les transporteurs (chauffeurs, équipes de quai)

La proposition est donc d’évoluer Toké d’une solution de pointage vers une plateforme WFM (Workforce Management) modulaire, dont l’usage de base reste inchangé pour les entreprises classiques, mais qui peut être enrichie par des modules pour les contextes plus exigeants.

1.4 Positionnement par rapport aux concurrents

Les solutions WFM internationales (NICE, Verint, Calabrio, Genesys, Aspect, Injixo) sont :

  • Tarifées en dollars (200-500 USD/agent/mois côté outils CC)
  • Conçues pour des structures > 500 agents
  • Découplées de la badgeuse / pointage (qu’on doit acheter à part)
  • Lourdes à déployer (intégrateur externe nécessaire, 6-12 mois de mise en route)

Toké + Modules occupe un espace vide sur le marché africain francophone :

  • Tarifé en FCFA, économiquement accessible aux PME
  • Conçu pour 50 à 2000 employés (sweet spot des entreprises africaines)
  • Pointage + planning + CC dans la même plateforme (pas d’intégration tierce)
  • Mobile-first, adapté aux smartphones Android low-end
  • Déploiement en semaines, pas en années
  • Hébergement local possible (souveraineté des données)

2. Cas d’usage et personas

2.1 Personas

Persona 1 — WFM Analyst (Workforce Management Analyst)

  • Profil type chez LMT : Analyste avec compétences Excel avancées, parfois statisticien junior.
  • Rôle : Construit le planning hebdomadaire à partir des prévisions de volume. Maintient les paramètres Erlang. Ajuste manuellement les shifts.
  • Outils actuels : Excel (calculateur Erlang Call Centre Helper + planning nominatif).
  • Temps consacré : 12-20h par semaine.
  • Frustrations : double saisie Excel, pas de visibilité sur la présence réelle, impossible d’évaluer si le planning est bon avant la semaine suivante.

Persona 2 — RTA Supervisor (Real-Time Adherence)

  • Profil type chez LMT : Superviseur opérationnel temps réel, chef d’équipe expérimenté.
  • Rôle : Surveille la présence en cours de journée. Détecte les retards, absences imprévues, agents en pause excessive. Ré-affecte les agents en intra-day.
  • Outils actuels : Inexistant. Présence visuelle, appels managers, tableau mural au mieux.
  • Frustrations : aveugle entre 8h et 22h, pas d’alerte précoce, dépend des signalements terrain.

Persona 3 — Superviseur d’équipe / Manager

  • Profil type chez LMT : Manager de 8 à 15 agents sur une campagne client (AMANA, ASSISTANCE, AUDACITY, etc.).
  • Rôle : Valide les mémos de ses subordonnés. Gère les ajustements ponctuels (échange de shifts, congés). Coache son équipe.
  • Outils actuels : Application Toké Manager (mobile) déjà disponible.
  • Frustrations : ne voit pas le planning prévisionnel dans Toké, doit consulter le S&E Excel reçu par mail.

Persona 4 — Agent CC (employé pointeur)

  • Profil type chez LMT : Téléconseiller, prend les appels selon ses skills (FR, EN, PIG, FFD).
  • Rôle : Pointe en arrivée, prend des appels, justifie les retards via mémo.
  • Outils actuels : Application Toké Pointage (mobile). Reçoit son planning hebdo par mail/WhatsApp.
  • Frustrations : son planning n’est pas dans l’app, doit se rappeler de ses shifts par d’autres canaux.

Persona 5 — DRH / Direction

  • Profil type chez LMT : Directeur RH, Directeur des Opérations, voire DG.
  • Rôle : Pilote la masse salariale, négocie les contrats clients, mesure la productivité globale.
  • Outils actuels : Rapports Excel mensuels, KPIs partiels, beaucoup d’opacité.
  • Frustrations : pas de vue consolidée, ROI des décisions difficile à évaluer, conformité légale à prouver.

7.6 Authentification et permissions

L’extension s’authentifie auprès de Toké Core comme un service de confiance :

  • Permissions étendues : compte de service avec rôle WFM_SERVICE (nouveau rôle à créer)
  • Les utilisateurs (WFM, RTA) s’authentifient auprès de l’extension via les mécanismes Toké (PIN/password/SSO selon évolution)

Périmètre de visibilité : le compte de service voit l’ensemble du tenant. Les permissions UI sont appliquées côté extension selon le rôle de l’utilisateur loggé.

  5. Le format CSV d’import des volumes est acceptable pour LMT comme entrée. Si LMT veut un connecteur direct à son ACD, c’est un développement supplémentaire à chiffrer.
